# cb21 — Development plan

Source of truth for order and status. Rules for working through it are in `CLAUDE.md`. Terms are defined in `CONTEXT.md`.

Status: `[ ]` todo · `[~]` in progress · `[x]` done · `[!]` blocked on the user.
Each step is one branch. **Manual** marks what only the user can verify.

## Technical decisions

- SwiftPM package plus a generated Xcode project (XcodeGen); the `.xcodeproj` is git-ignored.
- Two targets: `CB21Core` (no UI, Swift Testing) and `cb21` (menu bar, History window, Settings, pasteboard watcher).
- Swift 6 language mode. Warnings are errors in `CB21Core`. No SwiftLint or SwiftFormat.
- macOS 14 minimum. Ad-hoc signing, no notarization (ADR-0002).
- Phase gate: every step merged, `swift test` and `xcodebuild` pass on `main`, and the phase's manual checklist is done by the user (phases 3–6).

## Phase 3 — Capture and quick access

- [x] 3.1 `feat/pasteboard-protocol`: pasteboard protocol in Core and a fake for tests; capture rules (Skipped copies for Concealed and Transient, AutoGenerated captured, own writes ignored).
- [x] 3.2 `feat/pasteboard-watcher`: real `NSPasteboard` watcher in the app target feeding Capture.
  - Verified automatically: ran the built app against a throwaway data folder, `pbcopy` text was captured, a repeated copy stored once. Known limit: only the first pasteboard item is read, so copying several files at once keeps only the first.
- [x] 3.3 `feat/menu-previews`: preview text, thumbnail, file name and URL per Representation (in Core, tested).
- [x] 3.4 `feat/menu-history`: menu lists the 10 most recent Clips; clicking a Clip Recopies it. **Manual**

- [x] 3.5 `feat/pasteboard-access-notice`: first-launch message and System Settings link when access is denied. **Manual**
  - Verified automatically: builds. The denied state needs macOS 15.4 or later (`accessBehavior`), checked with `#available`; the System Settings link opens the general Privacy & Security pane.
  - **Manual:** in System Settings > Privacy & Security > "Paste from Other Apps", set cb21 to Deny (it appears after cb21 first reads the clipboard). The menu should show "cb21 can't read the clipboard" with a working Settings link. Setting it back to Allow should clear the message within a second.
- [x] 3.6 `feat/db-notice`: one-time notices for oversized Clips and database recovery in the menu. **Manual**
  - Verified automatically: real app with a corrupt `history.sqlite` moved it aside and started empty; a 105 MB copy was rejected and stored nothing; a small copy afterwards was stored.
  - **Manual:** the two menu messages themselves. Put garbage in `~/Library/Application Support/cb21/history.sqlite` (with cb21 quit) and launch: the menu shows "History was damaged and has been reset" with Dismiss. The oversized message appears once Settings can lower the storage Limit (step 5.2); check it then.

- [x] 5.1 `feat/settings-shell`: Settings pane with Shortcuts, History and General sections; settings persist.
  - Verified automatically: settings save/load/default tests in Core; app builds. **Manual:** menu "Settings…" (or Cmd-comma with the menu open) opens a window with Shortcuts, History and General sections; History shows 100 clips and 100 MB.
- [x] 5.2 `feat/limits-ui`: Limits controls with defaults (100 Clips, 100 MB) and the trim warning. **Manual**
  - Verified automatically: eviction count and trimming are covered by Core tests; app builds and launches.
  - **Manual:** Settings > History: change the two numbers, Apply is enabled only when valid and changed; lowering below the current History shows "Delete N older clips?" (Cancel restores the old numbers); Reset to Defaults gives 100 / 100 MB; values survive quitting and relaunching. With the storage limit at 1 MB, copying a larger image or text should show the "too large" notice in the menu (this also completes the 3.6 check).
- [x] 5.3 `feat/shortcut-validation`: shortcut rules in Core (modifier required, system shortcuts rejected), tested.
- [x] 5.4 `feat/history-shortcut`: shortcut recorder and global binding that toggles the History window. **Manual**
  - Verified automatically: settings persistence tests; a standalone Carbon test confirmed registering the same hotkey twice is refused (the basis of the conflict warning); app builds.
  - **Manual:** Settings > Shortcuts > "Open history": click, press e.g. Ctrl-Opt-V. It shows as ⌃⌥V and pressing it from any app toggles the History window. Try: no modifier (refused), Cmd-Space (refused), a shortcut another app already uses (refused with a message, old one stays). Reset clears it. The shortcut survives relaunch.
- [x] 5.5 `feat/pause-core`: Pause state with 5, 15 minute and until-resumed timers, always cleared at restart (in Core, tested).
- [x] 5.6 `feat/pause-ui`: menu item, distinct icon state and Pause shortcut. **Manual**
  - Verified automatically: Pause rules (skip, timers, resume, restart, Recopy while paused) are Core tests; app builds and launches. The menu, icon and hotkey need your hands.
  - **Manual:** menu > "Pause capture" offers 5 min, 15 min and until resumed; while paused the icon changes to a pause symbol and the menu shows "Resume capture". Copy something while paused: it must not appear in History, before or after resuming. A 5-minute pause ends by itself (try it, or trust the Core test). Quit and relaunch while paused: capturing again. Settings > "Pause / resume capture" shortcut toggles pause from any app; it is refused if it equals the History shortcut.

## Phase 5b — Accessibility tweaks (requested after Phase 5)

- [x] S3 `chore/assets`: move and convert the provided artwork: menu bar sprites (`Default.svg`, `Paused.svg`), app icon and README image (`CB21.png`).
  - Sources live in `design/` (menu bar SVGs) and `docs/assets/cb21.png` (README image and icon source). `swift scripts/make-assets.swift` regenerates the asset catalog: black template menu bar images at 18 pt (1x-3x) and the app icon on the 1024 grid. Note `cb21.png` is 828x825, not square, so it is scaled to fit; a 1024x1024 export would be crisper for the large icon sizes.
- [x] 5.7 `feat/status-item-menu`: replace SwiftUI `MenuBarExtra` with an `NSStatusItem` and `NSMenu` so the menu can be opened from code; use the sprites, swapping on Pause. **Manual**
  - Verified automatically: builds, launches, capture still works through the new service start; screenshots and accessibility are not permitted for the agent, so the icon and menu are unseen.
  - **Manual:** the menu bar shows the new clipboard sprite (Default); the menu has the same items as before, rebuilt fresh on every open; image clips show a thumbnail, links and files an icon. Pausing swaps the icon to the Paused sprite and back on resume. Light and dark menu bar both look right (template image).
- [x] 5.8 `feat/menu-shortcut`: optional global shortcut that opens the menu bar list itself; same validation and conflict rules as the other shortcuts. **Manual**
  - Verified automatically: persistence test; app builds. All three shortcuts now refuse a duplicate of each other (Core validator, covered by tests).
  - **Manual:** Settings > Shortcuts > "Open menu bar list": record e.g. Ctrl-Opt-M. Pressing it from any app opens the menu bar menu under the icon, as if clicked; Escape or clicking away closes it. Refused when equal to the other two shortcuts or a system one.
- [x] 5.9 `feat/history-copy-button`: a Copy button beside Delete in the History window: Recopy (the Clip becomes the most recent and goes on the pasteboard) and close the window. **Manual**
  - Verified automatically: Recopy ordering and not re-capturing are Core tests; app builds.
  - **Manual:** each row has a Copy button (two-pages icon) left of the trash. Clicking it closes the window, focus returns to the app you came from, and pasting there pastes that Clip. Reopen the window: the Clip is at the top and not duplicated. Double-click does the same.
- [x] 5.10 `feat/latest-clip-dot`: a dot marks the most recently used Clip in the History window. **Manual**
  - Verified automatically: builds. Interpretation: the dot sits on the top row, the most recently used Clip, which is also the one you last copied or Recopied.
  - **Manual:** a small accent-colored dot appears left of the first row only. Copy something new, or press Copy on an older Clip: the dot follows the Clip to the top.

- [x] S4 `fix/menu-latest-dot`: the most recent Clip is also marked with a dot in the menu bar list (5.10 only covered the History window). **Manual:** open the menu: a dot sits left of the top clip only.

- [x] S5 `fix/double-close-on-failed-open`: opening a corrupt database closed the connection twice (once in `init`'s failure path, once in `deinit`), a use-after-free that crashed parallel test runs about 1 time in 20 and could affect the app's corrupt-History recovery. Found from the macOS crash reports; fixed by clearing the pointer; 0 failures in 200 parallel runs afterwards.

- [x] S6 `fix/menu-shortcut-stacking`: pressing the open-menu shortcut repeatedly queued one reopen per press, because opening the menu from code blocks until it closes. The press is now judged at the moment it arrives and dropped if the menu is open or opening (`MenuOpenGate` in Core, 5 tests; the hotkey layer asks it before queueing anything).
  - Verified automatically: gate tests; app builds. The key presses themselves could not be simulated (no accessibility permission for the agent).
  - **Manual:** set the open-menu shortcut, press it once (menu opens), then press it 5 times quickly while it is open: nothing queues, and after you close the menu it does not reopen. Pressing it again after closing opens it normally. Opening the menu with the mouse and then pressing the shortcut also does nothing.

## Phase 7 — Inspect clips (CB-7)

Order: the stored facts first (7.1–7.3), then the logic in Core (7.4), then the screens (7.5–7.7).

- [x] 7.1 `feat/schema-migration`: versioned database migrations (`user_version`); the first one adds `source_app_name` to `clips` without touching existing rows. Tested against a database created with the old schema.
  - Verified automatically: 4 migration tests (fresh database, old-schema fixture keeps its Clips, migrating twice, a newer database is refused and never moved aside) and a dry run on a copy of the real History (2 Clips, version 0 to 1, column added, nothing set aside). Your real History migrates the first time this build runs; the step is additive and runs in a transaction.
- [x] 7.2 `feat/source-app`: `Clip` and `PasteboardSnapshot` carry an optional Source app; the real pasteboard fills it from the frontmost app at capture time (it can lag the copy by up to the 0.5 s poll interval); the store saves and lists it. Core tests with the fake pasteboard.
  - Verified automatically: Core tests (captured, none when unknown, kept on Recopy, survives the database); the real app recorded "iTerm2" for a `pbcopy` run from the terminal. Deviation from the Q4 answer: only the app name is stored, not the bundle id, since nothing displays or uses it yet (adding it later is one more migration).
- [x] 7.3 `feat/pdf-representation`: new `pdf` Representation kind for raw PDF data (`com.adobe.pdf`), ranked after images; previews and the menu show it as a PDF. Core tests.
  - Verified automatically: classify, preview and ranking tests; the real app captured a 2-page PDF placed on the pasteboard as `com.adobe.pdf` (stored as kind `pdf`). Menu and History rows label it "PDF" until 7.4 adds page counts. **Manual:** copy a page or selection from Preview or another PDF viewer and check it appears as a PDF in the menu.
- [x] 7.4 `feat/clip-metadata`: `ClipMetadata` in Core: all-Clip facts, text counts, image size and format (ImageIO), PDF pages and title (PDFKit), file facts and existence, link host. Tests with generated PNG and PDF fixtures and temp files.
  - Verified automatically: 14 tests with generated PNG and PDF fixtures and temp files (text counts incl. emoji, image size and format, PDF pages and title, file facts for existing, missing and PDF files, link host). ClipMetadata is plain data and cheap for text and links; image and PDF facts decode the data, so the app calls them off the main thread (7.6/7.7).
- [x] 7.5 `feat/row-subtitle`: History rows show a subtitle with relative time, size and Source app. **Manual**
  - Verified automatically: subtitle wording, units, the week cutoff, future timestamps and missing source app are Core tests; app builds and launches.
  - **Manual:** each History row shows a grey second line such as "5 min ago · 12 KB · Safari" (no source app for older Clips, so just time and size). The "5 min ago" part moves on by itself while the window stays open (within 30 seconds). The menu bar list is unchanged.
- [x] 7.6 `feat/detail-pane`: History window gets a Detail pane for a single selected Clip, with a hint for none or several; text view with counts and the 10,000-character cap, links, file facts. **Manual**
  - Verified automatically: the 10,000-character cap is Core tests (4); app builds and launches. The pane loads the Clip and its facts off the main thread (`Task.detached`) and ignores stale results when the selection changes (`.task(id:)`). Image, PDF and file previews are still to come in 7.7; their facts already show.
  - **Manual:** the History window is now wider with the list on the left and the Detail pane on the right. Select one Clip: text shows in full (selectable) with characters, words and lines; a link shows its URL and host; a file shows name, folder, kind, size and modified date, and "File no longer exists" if you moved or deleted it; images show dimensions and format; PDFs show pages and title. Every Clip also shows Copied, Last used, Stored size and Source app. Nothing selected or several selected show a hint. Try a text longer than 10,000 characters: it shows the cap note.
- [x] 7.7 `feat/image-pdf-preview`: scaled image, first PDF page and Quick Look file thumbnails, generated off the main thread and cached, with a "File no longer exists" state. **Manual**
  - Verified automatically: `PreviewRenderer` in Core has 9 tests (scale down but never up, aspect ratio, PDF first page at up to 2x, unreadable and missing content, a Quick Look thumbnail of a real temp file), stable over 40 repeated runs; app builds and launches. The app caches the last 30 pictures and renders them off the main thread.
  - **Manual:** select an image clip: the picture shows scaled to fit above its facts. Select a PDF clip (copy a page from Preview) or a PDF file copied in Finder: first page appears. Select a file such as a photo or document copied in Finder: a thumbnail appears; delete or move that file and select the clip again: "File no longer exists" and the saved facts remain. Click quickly between clips: no freezing, and the picture always matches the selected clip.
- [x] 7.8 `docs/readme-source-app`: README privacy section mentions the locally stored Source app and the new Detail pane.
