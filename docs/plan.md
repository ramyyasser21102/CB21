# cb21 — Development plan

Source of truth for order and status. Rules for working through it are in `CLAUDE.md`. Terms are defined in `CONTEXT.md`.

Status: `[ ]` todo · `[~]` in progress · `[x]` done · `[!]` blocked on the user.
Each step is one branch. **Manual** marks what only the user can verify.

## Technical decisions

- SwiftPM package plus a generated Xcode project (XcodeGen); the `.xcodeproj` is git-ignored.
- Two targets: `CB21Core` (no UI, Swift Testing) and `cb21` (menu bar, History window, Settings, pasteboard watcher).
- Swift 6 language mode. Warnings are errors in `CB21Core`. No SwiftLint or SwiftFormat.
- macOS 14 minimum. Ad-hoc signing, no notarization (ADR-0002).
- Phase gate: every step merged, `swift test` and `xcodebuild` pass on `main`, and the phase's manual checklist is done by the user (phases 3–6).

## Phase 2 — Storage core (`CB21Core`, test-first)

- [x] 2.1 `feat/clip-model`: `Clip` and `Representation` types, content equality.
- [x] 2.2 `feat/sqlite-store`: SQLite store open/migrate, insert and list Clips by last used, `secure_delete` on.
- [x] 2.3 `feat/duplicate-rule`: a copy equal to the top Clip is not stored; A, B, A stores A twice.
- [x] 2.4 `feat/recopy-ordering`: Recopy moves a Clip to the top without adding one.
- [x] 2.5 `feat/image-files`: image bytes saved as files beside the database, metadata in SQLite (preview thumbnails come with 3.3).
- [x] 2.6 `feat/delete-clips`: delete one, several or all Clips, removing rows and image files.
- [x] 2.7 `feat/limits-eviction`: item and storage Limits, least recently used evicted first, lowering a Limit trims.
- [x] 2.8 `feat/oversized-clip`: a Clip larger than the storage Limit is rejected with a reason.
- [x] 2.9 `feat/orphan-sweep`: startup removes image files with no row.
- [x] 2.10 `feat/corrupt-db-recovery`: unreadable database moved aside under a timestamped name, new empty History, notice flag set.

## Phase 3 — Capture and quick access

- [x] 3.1 `feat/pasteboard-protocol`: pasteboard protocol in Core and a fake for tests; capture rules (Skipped copies for Concealed and Transient, AutoGenerated captured, own writes ignored).
- [x] 3.2 `feat/pasteboard-watcher`: real `NSPasteboard` watcher in the app target feeding Capture.
  - Verified automatically: ran the built app against a throwaway data folder, `pbcopy` text was captured, a repeated copy stored once. Known limit: only the first pasteboard item is read, so copying several files at once keeps only the first.
- [x] 3.3 `feat/menu-previews`: preview text, thumbnail, file name and URL per Representation (in Core, tested).
- [x] 3.4 `feat/menu-history`: menu lists the 10 most recent Clips; clicking a Clip Recopies it. **Manual**
  - Verified automatically: builds, launches, capture feeds the model. The real menu could not be read (no assistive access for the agent).
  - **Manual:** run the Debug build, copy 3 or 4 different things (text, a link, an image, a file in Finder). Open the menu: newest first, text truncated, link and file icons, image thumbnail. Click an older item, paste somewhere: it pastes, moves to the top and does not appear twice.
- [x] 3.5 `feat/pasteboard-access-notice`: first-launch message and System Settings link when access is denied. **Manual**
  - Verified automatically: builds. The denied state needs macOS 15.4 or later (`accessBehavior`), checked with `#available`; the System Settings link opens the general Privacy & Security pane.
  - **Manual:** in System Settings > Privacy & Security > "Paste from Other Apps", set cb21 to Deny (it appears after cb21 first reads the clipboard). The menu should show "cb21 can't read the clipboard" with a working Settings link. Setting it back to Allow should clear the message within a second.
- [x] 3.6 `feat/db-notice`: one-time notices for oversized Clips and database recovery in the menu. **Manual**
  - Verified automatically: real app with a corrupt `history.sqlite` moved it aside and started empty; a 105 MB copy was rejected and stored nothing; a small copy afterwards was stored.
  - **Manual:** the two menu messages themselves. Put garbage in `~/Library/Application Support/cb21/history.sqlite` (with cb21 quit) and launch: the menu shows "History was damaged and has been reset" with Dismiss. The oversized message appears once Settings can lower the storage Limit (step 5.2); check it then.

## Phase 4 — History window and deletion

- [x] 4.1 `feat/history-window`: floating panel listing the full History with previews. **Manual**
  - Verified automatically: builds and launches. The window is built from `NSHostingController` + SwiftUI `List(selection:)`, so Shift/Cmd-click selection is the system behavior.
  - **Manual:** menu > "Open history…" opens a floating window with the full History (not just 10). Double-clicking a row Recopies it. The window comes to the front, and with no Clips shows the empty message.
- [x] 4.2 `feat/delete-ui`: per-Clip delete button and Delete key. **Manual**
  - Verified automatically: builds; deletion itself (rows and image files) is covered by `CB21Core` tests.
  - **Manual:** each row has a trash button that deletes only that Clip. Selecting a row and pressing Delete removes it. Check the Clip is gone from the menu too.
- [x] 4.3 `feat/multi-select`: Shift/Cmd-click multi-select, then delete. **Manual**
  - Verified automatically: builds.
  - **Manual:** Shift-click and Cmd-click select several rows; a "N selected" bar with "Delete Selected" appears, and the right-click menu offers "Delete N Clips". Delete removes exactly the selected Clips.
- [x] 4.4 `feat/clear-all`: Clear all with confirmation, from the menu and the window. **Manual**
  - Verified automatically: builds; `deleteAll` (rows and image files) is covered by `CB21Core` tests.
  - **Manual:** menu "Clear all…" and the window toolbar "Clear All…" both show a confirmation with the clip count. Cancel keeps everything; Clear All empties the menu and window. The menu item is disabled when History is empty.

## Phase 5 — Settings, shortcuts, Pause

- [x] 5.1 `feat/settings-shell`: Settings pane with Shortcuts, History and General sections; settings persist.
  - Verified automatically: settings save/load/default tests in Core; app builds. **Manual:** menu "Settings…" (or Cmd-comma with the menu open) opens a window with Shortcuts, History and General sections; History shows 100 clips and 100 MB.
- [x] 5.2 `feat/limits-ui`: Limits controls with defaults (100 Clips, 100 MB) and the trim warning. **Manual**
  - Verified automatically: eviction count and trimming are covered by Core tests; app builds and launches.
  - **Manual:** Settings > History: change the two numbers, Apply is enabled only when valid and changed; lowering below the current History shows "Delete N older clips?" (Cancel restores the old numbers); Reset to Defaults gives 100 / 100 MB; values survive quitting and relaunching. With the storage limit at 1 MB, copying a larger image or text should show the "too large" notice in the menu (this also completes the 3.6 check).

- [ ] 5.6 `feat/pause-ui`: menu item, distinct icon state and Pause shortcut. **Manual**
